# LAB 6 copy-on-write fork
- COW fork() creates just a pagetable for the child, with PTEs for user memory pointing to the parent's physical pages.
COW fork() marks all the user PTEs in both parent and child as not writable. When either process tries to write
one of these COW pages, the CPU will force a page fault. The kernel page-fault handler detects this case, allocates a
page of physical memory for the faulting process, copies the original page into the new page, and modifies the relevant
PTE in the faulting process to refer to the new page, this time with the PTE marked writeable. When the page fault handler
returns, the user process will be able to write its copy of the page.
- COW fork() makes freeing of the physical pages that implement user memory a little trickier. A give physical page may be
referred to by multiple processes' page tables, and should be freed only when the last reference disappears.
- 物理内存页必须保证在所有引用都消失后才能被释放，这里需要引用计数机制。

## implement copy-on-write
- 首先修改uvmcopy()，在复制父进程的内存到子进程的时候，不立刻复制数据，而是建立指向原物理页的映射，并将父子的页表项都设置为不可写
- 在risc.h中定义PTE_COW
- 在usertrap()中添加对page fault 的检测，并在当前访问的地址符合懒复制页条件时，对懒复制页进行实复制操作
- 同时copyout()由于是软件访问页表，不会触发缺页异常，所有需要手动添加同样的监视代码，检测接收到的页是否是一个懒复制页，若是，则执行实复制操作
- 实现懒复制页的检测（uvmcheckcowpage())与实复制（uvmcowcopy())操作
- 接下来，需要做页的生命周期管理，确保在所有进程都不使用一个页时才将其释放\
由于一个物理页可能被多个进程（多个虚拟地址）引用，并且必须在最后一个引用消失后才可以释放回收该物理页，所以一个物理页的生命周期内，需要支持以下操作：\
1. kalloc()：分配物理页，将其引用计数置为1
2. krefpage()：创建物理页的一个新引用，引用计数加1
3. kcopy_n_deref()：将物理页的一个引用实复制到一个新物理页上（引用计数为1），返回得到的副本页，并将本物理页的引用计数减1
4. kfree()：释放物理页的一个引用，引用计数减1；如果计数变为0， 则释放回物理页\
并且在除了 kalloc 的其他操作中，都使用了 acquire(&pgreflock); 和 release(&pgreflock); 获取和释放锁来保护操作的代码。这里的锁的作用是防止竞态条件（race-condition）下导致的内存泄漏。
