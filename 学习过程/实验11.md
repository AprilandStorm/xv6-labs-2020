# DMA
- DMA，全称是 Direct Memory Access（直接内存访问），指的是一种不经过 CPU，由外设直接与系统内存之间进行数据传输的技术。
- 通常情况下，外设（比如网卡、硬盘、显卡等）需要读取或写入数据时，都是通过 CPU 作为中介来完成的。这意味着 CPU 必须不断地处理这些数据传输请求，这会消耗大量的 CPU 资源，特别是在数据量很大的时候，会显著降低系统的整体性能。
- DMA 技术的出现就是为了解决这个问题。它通过一个专门的 DMA 控制器，允许外设直接读写内存，完全绕过 CPU。这就像是给了外设一把“钥匙”，让它们可以自行在内存中搬运数据，而不需要每次都找 CPU 帮忙。
- DMA 传输的工作流程
  1. 准备阶段：CPU 向 DMA 控制器发送指令，告诉它要传输的数据在内存的哪个位置（源地址）、要传到外设的哪个地址（目的地址），以及要传输多少数据（数据长度）。
  2. 传输阶段：CPU 释放总线控制权。DMA 控制器获得控制权后，直接指挥外设和内存之间进行数据传输。这个过程中，CPU 可以去执行其他任务，不用等待。
  3. 完成阶段：数据传输完成后，DMA 控制器会向 CPU 发送一个中断信号，通知 CPU 传输任务已经完成。CPU 收到信号后，就可以对这些数据进行后续处理。
- 为什么 DMA 如此重要？
  1. 减轻 CPU 负担：CPU 无需参与数据传输的全过程，可以专注于更重要的计算任务，大大提高了系统效率。
  2. 提高数据传输速度：外设和内存之间可以直接通信，避免了 CPU 作为一个中间环节带来的延迟，尤其是在处理大量数据（如视频、网络数据包）时，效果非常明显。
  3. 实现高并发：在 DMA 传输进行时，CPU 可以同时处理其他任务，这使得系统能够更有效地处理多个并发操作。
- DMA控制器与CPU的关系\
  我们可以把 DMA 控制器看作是 CPU 的一个“助手”或“数据搬运工”。
  1. CPU 下达命令：当需要进行 DMA 传输时，CPU 会通过总线向 DMA 控制器发送命令，告诉它传输任务的详细信息，比如源地址、目的地址和数据量。
  2. DMA 控制器接管总线：一旦 DMA 控制器接收到命令，它就会向 CPU 发送一个请求，要求获得总线的控制权。
  3. CPU 释放总线：CPU 响应请求后，会暂时释放对地址总线、数据总线和控制总线的控制权。
  4. DMA 独立传输：DMA 控制器接管总线，直接指挥外设和内存之间进行数据传输，这个过程完全不需要 CPU 参与。
  5. 任务完成通知：传输完成后，DMA 控制器会向 CPU 发送一个中断信号，告诉 CPU 任务已完成，CPU 就可以恢复对总线的控制权，并处理后续工作。

# 内存映射寄存器（Memory-Mapped Registers）
- 简称 MMR，是一种让 CPU 能够像访问内存一样来访问和控制 外设 的技术。
- 简单来说，计算机系统中的每个外设（例如网卡、显卡、硬盘控制器等）都有一些内部的寄存器，用来控制其行为或反映其状态。比如，网卡可能有一个寄存器用来设置发送速度，另一个寄存器用来检查是否有新的数据包到达。
- 为了让 CPU 能够与这些外设进行通信，需要一种机制来读写这些寄存器。内存映射就是这样一种机制。
- 它是如何工作的？\
  在内存映射中，系统设计者会将一部分物理内存地址空间分配给这些外设的寄存器。
  1. 物理地址映射：不是所有的物理地址都指向真正的内存芯片（如 RAM）。有一部分地址范围是预留出来的，专门用来“映射”到外设的寄存器。
  2. CPU 访问：当 CPU 想要读写某个外设的寄存器时，它只需执行一个普通的内存读或写指令，并使用该寄存器所对应的那个物理地址。
  3. 地址解码器：系统总线上的地址解码器会识别出这个地址不是指向 RAM，而是指向一个外设。它会将 CPU 的读写请求转发给对应的外设。
  4. 外设响应：外设收到请求后，会像响应内存一样，将数据从其内部寄存器读出或写入到其内部寄存器。
- 为什么使用内存映射？
  1. 简化编程：对于程序员来说，操作外设就像操作内存中的变量一样简单。你不需要特殊的 I/O 指令，只需要使用标准的内存读写指令 (mov) 就可以完成。这让驱动程序（driver）的编写变得更直接。
  2. 统一的地址空间：它将内存和外设的地址统一到一个地址空间里，简化了硬件设计。CPU 和其他设备可以通过相同的总线来通信，无需额外的专用总线。
  3. 支持更多的设备：通过分配不同的地址范围，系统可以轻松地支持更多的外设。
- 内存映射寄存器与端口I/O（Port I/O）的区别
  1. 端口 I/O：使用特殊的 I/O 指令（如 in 和 out）来读写外设的端口地址。它有自己独立的地址空间，与内存地址空间是分开的。
  2. 内存映射 I/O：使用普通的 内存读写指令 (mov) 来读写外设的寄存器，它们与内存共享同一个地址空间。
  目前，内存映射 I/O 是主流。它更灵活、更高效，并且能更好地利用现代 CPU 架构的优势。

# 什么叫虚拟索引，物理标记
- Cache 的基本结构\
  一个 Cache line 通常由三部分组成：数据块（Data Block）；索引（Index） → 决定查 Cache 时去哪个 set（集合）；标记（Tag） → 存放在 Cache line 的头，用来确认这个 line 对应的地址是不是我们要找的。
- 虚拟索引（Virtual Index）\
  索引位 是从 虚拟地址 (VA) 中取的。意味着：当 CPU 还没翻译 VA → PA 时，Cache 就能先用虚拟地址的低位 bits 去确定要查哪个 set；好处：Cache 查找和 TLB 查找可以并行，降低延迟。
- 物理标记（Physical Tag）\
  1. 每个 Cache line 会存一个 标记（Tag）。
  2. 如果标记用 物理地址 (PA) 来保存，就叫 物理标记。
  3. 查找时：先用 VA 的低位 bits 找到候选的 set（虚拟索引）。同时 TLB 把 VA → PA 翻译出来。对比候选行里的 物理标记 和 TLB 翻译出的 物理地址高位。如果匹配，就命中，否则 miss。
- 为什么这么设计？
  1. 纯虚拟 Cache（VIVT, Virtual Index, Virtual Tag），优点：完全不用等 TLB，特别快。缺点：可能有 别名 aliasing —— 不同虚拟地址映射到同一物理地址，Cache 里会存两份副本，数据不一致。
  2. 纯物理 Cache（PIPT, Physical Index, Physical Tag），优点：没有 alias 问题。缺点：必须等 TLB 翻译完成后才能查 Cache，延迟更高。
  3. 折中方案：VIPT（Virtual Index, Physical Tag）。索引用虚拟地址的 页内偏移部分（VA 和 PA 在页内偏移上是一样的）。标记用物理地址（来自 TLB）。好处：TLB 查 PA 和 Cache 查 set 可以并行，速度快。限制：Cache 大小不能太大，否则 index bits 会超出页内偏移 bits，导致 aliasing。
- 为什么需要 cache 的索引(index) 和标记(tag)？\
  CPU cache（L1/L2/L3）是个 哈希表：index：用来定位 cache 行所在的「槽」(set)，类似于哈希桶。tag：用来验证这个槽里是不是我要的那条数据。如果没有 tag，单靠 index，可能会错把别的数据当成我要的。
- 虚拟索引 vs 物理索引
  1. 虚拟索引 (Virtual Index).索引是用 虚拟地址 的一部分直接取的。好处：取 cache 的速度快，不用等地址翻译（page table / TLB）。坏处：多个虚拟地址可能映射到同一个物理地址（别名 aliasing），可能导致 cache 一致性问题。
  2. 物理标记 (Physical Tag). 即使你用虚拟地址索引，最终要确认是不是我要的那一行，必须用物理地址的 tag 比较。因为物理地址才是全局唯一的，虚拟地址不能保证唯一。
- 所以典型做法是：Index（哪一组槽位）用虚拟地址的低位（翻译前就能拿到，快）。Tag（验证是不是我的数据）用物理地址的高位（要等TLB翻译后才能知道）。
  
# 什么是RCU？（Read-Copy Update）
- RCU是一种Linux内核里广泛使用的同步机制，主要解决这样的问题：
  1. 读多写少的共享数据结构（例如路由表、任务列表等）。
  2. 读者不需要加锁，写者通过拷贝修改数据，并在合适时机替换。
  3. 避免了传统读写锁对读路径的性能影响。
- RCU critical 区域的定义：一个 RCU critical 区域（RCU临界区） 指的是在内核中，代码处于 受 RCU 保护的数据访问 的那一段。\
  它通常写作：
  ```
  rcu_read_lock();
  /* 这里是RCU critical 区域 */
  p = rcu_dereference(shared_ptr);
  /* 访问受RCU保护的数据结构 */
  rcu_read_unlock();
  ```
  在这个区域内，你可以安全地读取RCU保护的数据结构，即使写者正在更新它。
- 关键特性
  1. 无阻塞：读者几乎没有开销，不会阻塞。
  2. 保证数据有效：在 rcu_read_lock() 和 rcu_read_unlock() 之间，指针不会被释放。即使写者更新了数据，旧的数据也会延迟到所有读者退出RCU临界区后才释放。
  3. 不是互斥：不同读者可以同时进入RCU critical 区域。

# 实验11 net 写驱动程序，实现驱动程序可以发送和接收数据包

## DMA 与环形缓冲区 (Ring Buffer)
- 在深入代码之前，必须理解两个核心概念：
  1. DMA (Direct Memory Access, 直接内存访问): 为了提高效率，现代网卡不依赖 CPU 来回搬运网络数据。相反，CPU 会在内存中准备好数据，然后告诉网卡“数据在这里，你自己去拿”，或者告诉网卡“把收到的数据放到这里”。这个由硬件（网卡）直接读写内存的过程就是 DMA。
  2. 环形缓冲区 (Ring Buffer): 为了实现 DMA，驱动和网卡需要一个共享的数据结构来协调工作，这就是环形缓冲区。它通常是一个描述符（descriptor）数组。\
     发送时：驱动程序将一个数据包的内存地址和其他信息填入一个“描述符”，然后将描述符放入发送环形缓冲区（Tx Ring）。网卡会自己读取这些描述符，找到数据包，并通过网络发送出去。\
     接收时：驱动程序预先分配好一些空的内存缓冲区，并将它们的地址填入接收环形缓冲区（Rx Ring）的描述符中。当网卡收到数据包后，它会找一个可用的描述符，将数据包通过 DMA 放入对应的内存缓冲区，然后通知驱动程序。
- 代码：见 net分支的kernel/net.c
- e1000_init 函数的完整流程如下：
  1. 准备工作：保存寄存器地址，初始化锁。
  2. 硬件复位：将网卡恢复到干净、可预测的状态。
  3. 设置发送机制：初始化发送环形缓冲区，将所有描述符标记为空闲，并把缓冲区的地址和长度告诉网卡。
  4. 设置接收机制：为接收环形缓冲区预分配好内存，并将这些空缓冲区的地址告诉网卡，让它有地方存放收到的数据。
  5. 配置网卡参数：设置自己的MAC地址，配置发送和接收单元的基本工作模式（如启用、接收广播、自动填充等）。
  6. 开启中断：最后一步，告诉网卡在完成接收数据包后通过中断来通知 CPU。
